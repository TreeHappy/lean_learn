# Generating the figures with Vizagrams

The images in `docs/figures/` (used by `docs/shooting-method.md`) are
generated by a Lean program, not by hand or by an external scripting
language. The generator is built on
[Vizagrams](https://github.com/arademaker/vizagrams), a Lean 4
diagramming/visualization DSL that models a drawing as geometric primitives
(`Geom`) with styles (`Style`) and renders them to SVG.

## How it works

```console
make figures          # = cd lean && lake exe gen-figures
```

writes every SVG referenced by `docs/shooting-method.md` into
`docs/figures/`.

The three Lean modules involved:

| File | Role |
|---|---|
| `lean/Brane/Figures/Basic.lean` | the Catppuccin **Latte** palette (per the [Catppuccin style guide](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md)), `Prim` shorthands (`primLine`, `primPolygon`, `primArrow`, `primText`, …), and the oblique 3D→2D projection |
| `lean/Brane/Figures/ShootingFigures.lean` | the nine figure builders |
| `lean/Brane/Figures/Gen.lean` | SVG serialization and the `gen-figures` executable |

### The same definitions run the figures

The pipeline in `Shooting.lean` is *polymorphic in the number type*: every
definition (`partialX`, `geoAccel`, `field`, `eulerStep`, `rk4Step`,
`shoot`, …) is quantified over a `GeoKernel` class — the six partial
derivatives of a height function plus the handful of numerals the formulas
need. There are two instances:

- `K = ℝ` — the partials are Mathlib's `deriv` (the mathematical definition,
  via `DiffGeom.partialX`, …). This instance is `noncomputable`; the proofs
  live here.
- `K = Float` — the partials are central finite differences. This instance
  is computable, and `lake exe gen-figures` runs the pipeline through it.

So there is no "mirror" module: `shootPositions rk4Step bowlHeight …` in
`ShootingFigures.lean` is literally the `shoot`, `rk4Step` and `bowlHeight`
the document quotes, instantiated at `Float`. The figures are genuinely
*computed from the mathematics the document describes*:

- `tangents.svg`, `normal.svg` — `tangentX` / `tangentY` / `normal`
  evaluated numerically at a point of the bowl;
- `euler-drift.svg` — real trajectories from `shoot eulerStep` vs
  `shoot rk4Step` on `bowlHeight` (the drift shown is Euler's actual
  error);
- `rk4-slopes.svg` — the actual RK4 increments `k₁ … k₄`;
- `distorted-map.svg` — a computed geodesic in the parameter plane.

Only `geodesic-rule.svg` is purely schematic.

### SVG serialization

Vizagrams' renderer targets ProofWidgets HTML (for the Lean infoview). For
file output, `Gen.lean` serializes Vizagrams' `Array Prim` directly to
standalone SVG — figures are authored in y-up coordinates and the serializer
flips y into SVG screen space. All label text is centered.

## Vendoring note

Vizagrams is **vendored** into this repository as `lean/Vizagrams/`
(Apache-2.0, `lean/Vizagrams-LICENSE`), pinned to upstream commit `68931c4`
with one patch: upstream imports `Mathlib.Data.Matrix.Notation`, which was
renamed to `Mathlib.LinearAlgebra.Matrix.Notation` in current Mathlib.
Vendoring was necessary because upstream pins Mathlib `master` and does not
build against the release this project uses.

## Toolchain note

The project uses Lean/Mathlib **v4.34.0** (down from v4.35.0) for Vizagrams
compatibility. The `mathlib` require must stay **last** in
`lean/lakefile.toml` (see the comment there).

## PNG conversion (optional)

The markdown references the SVGs directly; browsers render them natively.
If you need PNGs, use any SVG rasterizer, e.g.
[`resvg`](https://github.com/linebender/resvg):

```console
resvg docs/figures/euler-drift.svg euler-drift.png
```
